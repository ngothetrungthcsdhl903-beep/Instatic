# Decisions

Product decisions that override earlier notes in this tree. When two entries conflict, the later one wins. Implementation detail lives in `design-system/DESIGN_SYSTEM.md` and the code it names.

## Fake glass on all chrome

The whole UI chrome — panels, toolbars, sidebars, inspectors, popovers, menus, dialogs, toasts, and tooltips — uses a **fake glass** material. The canvas and breakpoint frames stay solid (`--k-color-bg-canvas`, frame fill `--k-color-bg-surface`). Full-viewport scrims stay a flat scrim.

This replaces both “glass only on floating chrome” and any real `backdrop-filter` recipe. Do not set `backdrop-filter` or `-webkit-backdrop-filter` on chrome. `--k-material-*-blur` is `0px`. Small popovers use the same material; they do not get a special blur.

Each level (`thin`, `regular`, `thick`), in light and dark, is generated by `design-system/gen.py`:

- Semi-opaque fill, about 72% / 80% / 85% (`--k-material-*-bg`).
- Top-to-bottom sheen (`--k-material-*-sheen`).
- 1px inner top highlight (`inset 0 1px 0 var(--k-material-*-highlight)`).
- Soft shadow (`--k-material-*-shadow`).
- Feathered edges from the intersected `--k-material-*-feather-y` and `--k-material-*-feather-x` masks (6px).
- Very light tiled noise, `url('/brand/noise.png')`, a cached 64×64 bitmap. Not an SVG filter.

`src/styles/materials.css` paints that recipe when an element has `data-k-material="thin|regular|thick"`. The fill sits on `::before` so the feather mask does not clip children. Scrollports that would scroll the mask away paint the same tokens as their own background and skip the mask. `prefers-reduced-transparency: reduce` resolves every level to `--k-material-solid-fallback` (sheen, noise, and shadow off; feather mask opaque).

Drag stays on the compositor: no live filter, no backdrop blur, noise is one static image. `src/__tests__/architecture/no-backdrop-filter.test.ts` rejects `backdrop-filter` in admin, ui, and style CSS.

## Design system is the source of truth

`design-system/gen.py` generates `tokens.json` and `tokens.css`. Do not hand-edit the generated files. `src/styles/globals.css` imports `tokens.css`. Keijam color, type, layout, and material tokens are `--k-*`.

The earlier `--kj-accent` ramp (`#2A68F1`) is retired. The accent is `--k-color-accent` (light `#0A66E0`, dark `#1F6FEB`) plus the generated hover, pressed, subtle, text, and on-accent tokens. Classic admin surfaces that still read `--bg-*` / `--text-*` from `globals.css` keep those tokens until they move onto `--k-*`. New chrome uses `--k-*`.

`python3 check.py` in `design-system/` must report `FAILS 0`.

## Inputs at rest

Text inputs, selects, search, and color inputs use `border: 1px solid var(--k-color-control-border)` at rest. That border is a visible neutral that clears WCAG 1.4.11 at 3:1 on `bg-panel` and `bg-control`. Hover uses `--k-color-border-strong`. Focus uses a 1px `--k-color-accent` border plus the focus ring. This replaces the earlier spec that set the rest border to 0 alpha.

## Layout reference

The editor layout and workflow follow Framer: left Pages / Layers / Assets, breakpoint frames side by side, a right inspector (position, size, layout, styles, effects, interactions), and a top toolbar with insert plus preview/publish. Figma UI3 is not the layout reference. Do not copy Framer brand assets, code, or text. Reference the public builder only for interaction ideas.

## Type and icons

UI text is Inter (the variable face already in `globals.css`). Do not ship San Francisco. The Keijam editor uses Lucide (`currentColor`, stroke from `--k-control-icon-stroke`). The rest of the admin stays on `pixel-art-icons`. Do not paste Lucide paths in as inline SVG.

## Mark

The product mark is the official monochrome logo under `public/brand/`. It follows the surrounding text color (`currentColor` or a mask). It is not painted with the accent. PNG icons stay the official black rasters. Favicon, apple-touch icon, the web manifest, the loading screen, and the README use those files.
